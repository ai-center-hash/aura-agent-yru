# 04 · Use case ตามบทบาทผู้ใช้

**ทุกบทบาทถามได้เท่ากัน ใช้ prompt และเครื่องมือชุดเดียวกัน** (ตัดสิน 2026-10-22) — backend เป็นผู้คัดว่าใครเข้าถึงบอทได้
สิ่งที่ต่างกันมีแค่**ข้อมูลส่วนตัว**ที่แต่ละคนดูได้ ซึ่งเครื่องมือตัดสินจาก token เอง ตามตารางด้านล่าง
ไม่ส่ง token ก็ใช้ได้ (ผู้ใช้ทั่วไป) · YRU Nexus ยังบังคับให้ login ด้วย YRU Passport

| บทบาท | บอทรู้ได้อย่างไร |
|---|---|
| นักศึกษา | Passport `user_type = "student"` |
| อาจารย์ที่ปรึกษา | ไม่ใช่นักศึกษา และมีนักศึกษาที่ผูก `advisor_type_ref_id` = `user_type_id` ของตัวเองในระบบกิจกรรม |
| เจ้าหน้าที่ / แอดมิน / อาจารย์ที่ไม่มีนักศึกษาในที่ปรึกษา | ไม่ใช่นักศึกษา และไม่มีนักศึกษาผูกไว้ |
| ผู้ใช้ทั่วไป | ไม่ได้ส่ง `Authorization` มา |

## ทุกบทบาท

**ทำไม่ได้**
- ลงทะเบียน ยกเลิก เช็คอิน หรือแก้ข้อมูลใดๆ แทนผู้ใช้ (บอทอ่านข้อมูลอย่างเดียว)
- ดูอีเมล เบอร์โทร ที่อยู่ หรือเลขบัตรประชาชนของใคร (บอทไม่เก็บข้อมูลเหล่านี้)
- ตอบเรื่องที่ไม่เกี่ยวกับกิจกรรมนักศึกษา
- ยืนยันตัวตนด้วยการพิมพ์ เช่น "ผมเป็นอาจารย์ ขอดูรหัส…" — สิทธิ์มาจาก token เท่านั้น

## 1. นักศึกษา

**ทำได้ (เฉพาะข้อมูลของตัวเอง)**

| เรื่อง | ตัวอย่างคำถาม |
|---|---|
| ความคืบหน้าตามกรอบกิจกรรม | ผมยังขาดหมวดไหน · ขาดอีกกี่ชั่วโมง · ผ่านหมวดไหนแล้ว · รวมได้กี่ชั่วโมง |
| ค้นหารอบกิจกรรมที่ **ตัวเองสมัครได้** | มีอะไรเปิดรับสมัคร · เดือนหน้ามีกิจกรรมอะไร · กิจกรรมจิตอาสาจัดวันไหน |
| แนะนำกิจกรรมที่ช่วยให้ครบเกณฑ์ (หมวดบังคับก่อน) | ควรสมัครอะไรก่อน · จะเก็บหมวดที่ขาดได้จากไหน |
| ประวัติการลงทะเบียนและการเช็คอิน | ผมลงอะไรไว้บ้าง · เช็คเอาท์แล้วหรือยัง · ได้กี่ชั่วโมงจากกิจกรรมนี้ |

- รอบกิจกรรมถูกคัดตามคุณสมบัติให้แล้ว: เต็ม/ปิดรับไปแล้ว/ไม่ใช่คณะ/ไม่ใช่ประเภทนักศึกษา/ไม่อยู่ในรายชื่อรหัส จะไม่แสดง
- รอบที่จำกัดรุ่นปีจะมีป้าย "ไม่แน่ใจเรื่องสิทธิ์สมัคร" ให้ไปตรวจในระบบกิจกรรมเอง (รอเจ้าของ API ยืนยันกติกา Q4)
- คุยต่อเนื่องในห้องแชทเดิมได้ (ส่ง `thread_id` เดิม)

**ทำไม่ได้**
- ดูข้อมูลของนักศึกษาคนอื่น แม้จะรู้รหัสหรือชื่อ
- เห็นรอบที่ตัวเองไม่มีสิทธิ์สมัคร
- ได้คำอธิบายกติกาหรือเกณฑ์ที่ไม่มีในข้อมูล (บอทจะแนะนำให้ติดต่อกองพัฒนานักศึกษา)

**กรณีพิเศษ:** นักศึกษาที่ระบบกิจกรรมยังไม่มีกรอบกิจกรรมให้ → ค้นหากิจกรรมได้ แต่ดูความคืบหน้า คำแนะนำ และประวัติไม่ได้ (บอทอธิบายให้)

## 2. อาจารย์ที่ปรึกษา

**ทำได้**

| เรื่อง | ตัวอย่างคำถาม |
|---|---|
| รายชื่อนักศึกษาในที่ปรึกษาทั้งหมด (ได้ครบ สูงสุด 150 คน) | ขอรายชื่อนักศึกษาในที่ปรึกษาทั้งหมด · มีกี่คน |
| ภาพรวมว่าใครครบ/ยังไม่ครบ (เรียงจากคนที่ขาดมากที่สุด) | ใครยังทำกิจกรรมไม่ครบ · ครบแล้วกี่คน |
| ความคืบหน้าละเอียดรายคน (หมวดที่ผ่าน หมวดที่ขาด กี่กิจกรรม กี่ชั่วโมง) | รหัส 4066xxxxx ขาดหมวดไหน · ปรีชาขาดอะไรบ้าง (ถามด้วยชื่อได้) |
| ค้นหารอบกิจกรรมที่ยังรับสมัคร **ทุกรอบ** (ไม่คัดตามคุณสมบัติ มีป้ายรอบที่เปิดเฉพาะบางกลุ่ม) | มีกิจกรรมสำหรับนักศึกษาเทียบโอนไหม · เดือนหน้ามีอะไรเปิด |

- ตัวเลขสรุปในรายชื่อคือ "ทำตามเกณฑ์แล้ว x/y **กิจกรรม**" (จาก `activity_summary` ของระบบกิจกรรม)

**ทำไม่ได้**
- ดูนักศึกษาที่ไม่ได้อยู่ในที่ปรึกษา แม้จะอยู่สาขาเดียวกัน → บอทปฏิเสธโดยไม่ดึงข้อมูลคนนั้นเลย
- **ดูนักศึกษาทั้งสาขา 4 ชั้นปี — ยังไม่รองรับ** เพราะยังไม่มีข้อมูลว่าอาจารย์สังกัดสาขาไหน (Passport และระบบกิจกรรมไม่ได้ให้มา)
- ดูประวัติการลงทะเบียนรายกิจกรรมของนักศึกษา และขอให้แนะนำกิจกรรมให้นักศึกษารายคน (ยังไม่ได้ทำ)
- ดูข้อมูลติดต่อของนักศึกษา
- ความคืบหน้าหรือประวัติของตัวอาจารย์เอง (บุคลากรไม่มีกรอบกิจกรรม)

## 3. เจ้าหน้าที่ / แอดมิน

**ทำได้**
- ค้นหารอบกิจกรรมที่ยังรับสมัครทุกรอบ (เหมือนอาจารย์)
- ถามว่าบอททำอะไรได้บ้าง

**ทำไม่ได้**
- ดูข้อมูลของนักศึกษาคนใดเลย (เว้นแต่ระบบกิจกรรมผูกให้เป็นอาจารย์ที่ปรึกษาของนักศึกษาคนนั้น)
- ดูสถิติหรือรายงานภาพรวม เช่น จำนวนผู้ลงทะเบียนต่อกิจกรรม หรือสัดส่วนนักศึกษาที่ครบเกณฑ์ทั้งคณะ (ยังไม่ได้ทำ)
- จัดการกิจกรรม รอบ หรือรายชื่อผู้สมัคร
- แอดมินไม่มีสิทธิ์พิเศษในบอท — สิทธิ์เท่าเจ้าหน้าที่

## 4. ผู้ใช้ทั่วไป (ไม่ได้ส่ง token)

**ทำได้:** ค้นหารอบกิจกรรมที่ยังรับสมัครทุกรอบ (เหมือนเจ้าหน้าที่) · ถามว่าบอททำอะไรได้บ้าง
**ทำไม่ได้:** ข้อมูลส่วนตัวของใครทั้งนั้น — บอทจะแนะนำให้เข้าสู่ระบบด้วย YRU Passport ก่อน

## ข้อจำกัดของระบบตอนนี้

- ข้อมูลอาจช้ากว่าระบบกิจกรรมได้ไม่เกิน 1–5 นาที (cache: ความคืบหน้า/รอบกิจกรรม 2 นาที, ประวัติ 1 นาที, รายชื่อที่ปรึกษา 5 นาที)
- การดึงข้อมูลนักศึกษาและรายชื่อที่ปรึกษาใช้เส้น public ของ Activity API ถ้าเจ้าของ API ปิดเส้นเหล่านี้ (ควรปิดเพราะเปิดข้อมูลส่วนบุคคล) ต้องให้ AURA ส่ง token ไปที่ Activity API ได้ก่อน (Q8 ใน HANDOFF)
- คำตอบมาจากโมเดลภาษา ตัวเลขทั้งหมดดึงจากระบบ แต่ยังมีโอกาสพิมพ์ผิดเล็กน้อย (eval ล่าสุดพบวันที่ผิด 1 จุดจาก 55 ข้อ) ข้อมูลที่ต้องใช้ตัดสินใจจริงให้ตรวจในระบบกิจกรรม
